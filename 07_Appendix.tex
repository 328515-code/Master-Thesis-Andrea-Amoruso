The standard window is iterations 2700--3000 inclusive ($N=301$). Nitrogen A at $5\,\mathrm{m\,s^{-1}}$ instead uses iterations 1072--1372, also with $N=301$. For a response $R$, the statistic reported is
\[
CV_R=\frac{100}{|\overline R|}
\sqrt{\frac{1}{N}\sum_{i=1}^{N}(R_i-\overline R)^2}.
\]
These iterative variations are not uncertainty bounds. The tool recovers force error bars as $\sigma_F=|\overline F_x|CV_F/100$.

\section[Reproducing the Response Fit]{Independent Reproduction of the Response Fit}
\label{sec:app_plotly_script}

The executable implementation is provided in \path{design_tool/model.py}, with plotting separated into \path{design_tool/charts.py}. For either force or pressure loss, let $R_i$ be the three terminal means. Minimizing $\sum_i(R_i-k_RU_i^2)^2$ gives
\[
k_R=\frac{\sum_i U_i^2R_i}{\sum_i U_i^4},\qquad
\widehat R(\dot m)=k_R\left(\frac{\dot m}{\rho A_{\mathrm{in,mesh}}}\right)^2.
\]
The same procedure is applied independently to each gas and obturator. It fits the available means with equal weights and does not force the quadratic function through all three points.

\subsection{Reproduction example}
\begin{lstlisting}[language=Python,numbers=none,caption={Independent hydrogen A check, run from the repository root.}]
import csv
from pathlib import Path

source = Path("design_tool/data")
with (source / "final_high_pressure_responses.csv").open() as f:
    rows = [r for r in csv.DictReader(f)
            if r["gas"] == "H2" and r["obturator"] == "A"]
u = [float(r["velocity_m_s"]) for r in rows]
force = [float(r["mean_axial_force_N"]) for r in rows]
drop = [float(r["mean_pressure_drop_kPa"]) for r in rows]
def fit(values):
    return sum(v*v*y for v, y in zip(u, values)) / sum(v**4 for v in u)

rho, area = 33.77, 4.658925e-5
mass = 15.0 / 1000.0  # g/s to kg/s
speed = mass / (rho * area)
print("Force [N]:", fit(force) * speed**2)
print("Pressure loss [kPa]:", fit(drop) * speed**2)
\end{lstlisting}

% At $15\,\mathrm{g\,s^{-1}}$ hydrogen, this gives $U_{\mathrm{in}}\simeq9.534\,\mathrm{m\,s^{-1}}$, $\widehat F_x\simeq20.249\,\mathrm{N}$ and $\widehat{\Delta p}\simeq120.28\,\mathrm{kPa}$ for A. Its projected Mach number is approximately $0.0685$, below $0.3$, and the selected mass flow lies within the sampled interval.

The calculation reproduces a fitted CFD load; interpreting it as a spring requirement still requires the mechanical closing direction and the remaining force balance.

For a reproducibility check, retain the original CSV precision, use the meshed inlet area and convert the input to kg/s before evaluation. A fit using rounded chapter tables, a nominal inlet area or an unconverted g/s input will produce a different result. The application tests additionally exercise boundary handling, invalid inputs, file integrity and exported status information.


\paragraph{Numerical checks example}
A reproduction should recover $20.249\,\mathrm{N}$ and $120.28\,\mathrm{kPa}$ for hydrogen A at $15\,\mathrm{g\,s^{-1}}$, within the rounding shown above. Classification checks should use the full-precision input data and boundary calculation:
\begin{enumerate}
\item At zero flow, the formal force and pressure loss are zero.
\item At the calculated $\dot m_{0.3}$ for any gas and geometry, the estimated Mach number is $0.3$ and both design outputs are withheld.
\item For nitrogen A at its upper sampled flow, $336.38743\,\mathrm{g\,s^{-1}}$, the projected Mach screen takes priority over coverage: the design outputs are withheld even though this flow corresponds to a simulated inlet velocity.
\end{enumerate}
These checks verify units and decision logic, it is not additional validation of the CFD model.

\section{Case preparation}
\label{sec:app_doe_gen}

The following code lines, document the 24-case factor combinations and preserves the starting template. It is an illustrative reconstruction, not the original submitted script. The clean template contains the tokens \texttt{FLUX\_VALUE}, \texttt{NU\_VALUE} and \texttt{RHO\_VALUE} in the indicated files. The geometry names below follow the documented A-B-C-D mapping and must match the supplied STL files.

\begin{lstlisting}[language=Python,numbers=none,basicstyle=\ttfamily\footnotesize,caption={DoE case generation with explicit template checks.}]
from itertools import product
from pathlib import Path
import shutil

fluids = {"H2": ("33.77", "2.709e-07"),
          "N2": ("481.352", "7.932e-08")}
shapes = {"A": "3Fori_1p5mm.stl", "B": "3Fori_3mm.stl",
          "C": "6Fori_1p5mm.stl", "D": "6Fori_3mm.stl"}
base, stls = Path("CASE_BASE"), Path("Geometrie_STL")
target = Path("DoE_Cases")
for gas, speed, obt in product(fluids, (5, 10, 15), shapes):
    rho, nu = fluids[gas]
    edits = {
        "0/include/initialConditions": ("FLUX_VALUE", str(speed)),
        "constant/physicalProperties": ("NU_VALUE", nu),
        "system/forces": ("RHO_VALUE", rho),
    }
    
    texts = {}
    for name, (token, value) in edits.items():
        text = (base / name).read_text()
        if text.count(token) != 1:
            raise ValueError(f"Expected one {token}: {name}")
        texts[name] = text.replace(token, value)
    shape = stls / shapes[obt]
    if not shape.is_file():
        raise FileNotFoundError(shape)
    case = target / gas / f"Sim_{gas}_Flux{speed:02d}_Obt_{obt}"
    if case.exists():
        raise FileExistsError(case)
    shutil.copytree(base, case)
    for name, text in texts.items():
        (case / name).write_text(text)
    shutil.copyfile(shape, case / "constant/geometry/wallObt.stl")
\end{lstlisting}

Case creation alone does not establish a valid mesh or solution. Before submission, an inspection of patch names, active force density and geometry assignment needs to be performed.

\section{Case execution and data retrieval}
\label{sec:app_slurm_scripts}

The sequence below summarizes the meshing and solving stages for an OpenFOAM~10 case. It is an execution outline: the account, partition, modules, memory and wall-time requests depend on the cluster configuration, these in particular are specific for the ARIES cluster \cite{hpc_aries}. Here \texttt{NPROCS} must match \texttt{numberOfSubdomains} in the case's decomposition configuration. It has to run only inside a generated case.

\begin{lstlisting}[language=bash,numbers=none,caption={Illustrative parallel execution sequence after environment setup.}]
set -euo pipefail
: "${NPROCS:?Set NPROCS to the decomposition count}"
blockMesh > log.blockMesh 2>&1
surfaceFeatures > log.surfaceFeatures 2>&1
decomposePar -copyZero > log.decomposePar 2>&1
mpirun -np "$NPROCS" snappyHexMesh -overwrite -parallel \
  > log.snappyHexMesh 2>&1
mpirun -np "$NPROCS" checkMesh -parallel > log.checkMesh 2>&1
# Review mesh quality before running the following solver step.
mpirun -np "$NPROCS" simpleFoam -parallel > log.simpleFoam 2>&1
\end{lstlisting}

Each simulation run folder, for the successive elaboration, has been downloaded locally using the \texttt{scp protocol}. The full result folder has been downloaded to get full access to all the simulation data and run the tool.

\subsection{Interpreting the output}
Select the gas and threshold in g/s, then compare all four geometries. The plots and exported CSV distinguish:
\begin{description}
\item[Within the sampled range:] a regression estimate supported by the computed points, subject to their numerical limitations.
\item[Extrapolation:] additional CFD is needed before spring selection, even if the estimated Mach number is below $0.3$.
\item[Mach limit reached:] design force and pressure fields are blank. A separately labelled formal force projection is not a design load. This rule takes priority over the sampled range classification.
\end{description}

The CSV retains the state, area, fit mismatch, variability, revision and force convention. Zero flow returns the imposed zero-load limit but is classified as extrapolation; negative or non-finite input is rejected. No output defines spring stiffness or certifies closure.
