The standard window is iterations 2700--3000 inclusive ($N=301$). Nitrogen A at $5\,\mathrm{m\,s^{-1}}$ instead uses iterations 1072--1372, also with $N=301$. For a response $R$, the reported statistic is
\[
CV_R=\frac{100}{|\overline R|}
\sqrt{\frac{1}{N}\sum_{i=1}^{N}(R_i-\overline R)^2}.
\]
These iterative variations are not uncertainty bounds. The tool recovers force error bars as $\sigma_F=|\overline F_x|CV_F/100$.

\section{Field Diagnostics and Contour Conventions}
\label{sec:app_field_diagnostics}

Integral means and saved-volume diagnostics have different sampling histories. All hydrogen fields and all nitrogen fields except A at $5\,\mathrm{m\,s^{-1}}$ are evaluated at iteration 3000. For that exception, the latest complete velocity volume is iteration 1000, the integral history ends at 1372 and the archived wall diagnostic is at 1300. These three indices must remain distinct.

The velocity maximum used by the tool is obtained from the original cell-centred field across all processor subdomains. A maximum from an interpolated longitudinal slice is a different quantity. The channel-region slice diagnostic is restricted to $0.035\leq x\leq0.046\,\mathrm{m}$ on $y=0$ and $z=0$; neither plane intersects every channel.

The projection is $Ma_{\mathrm{est}}=\alpha\dot m/(\rho A_{\mathrm{in,mesh}}a_{\mathrm{ref}})$.
The nitrogen A boundary is slightly below its largest sampled mass flow, even though its observed maximum is $0.2979$: the largest amplification ratio comes from the lower-velocity case. This envelope is more restrictive than using only the final high-velocity point, but is not a guaranteed bound at uncomputed conditions.

For contour comparison, camera, planes and spatial scale are fixed. Within each gas, one common range covers all geometries and speeds: hydrogen uses $0$--$140.98\,\mathrm{m\,s^{-1}}$ and $-224.23$--$299.35\,\mathrm{kPa}$; nitrogen uses $0$--$140.61\,\mathrm{m\,s^{-1}}$ and $-3300.13$--$4272.71\,\mathrm{kPa}$. Equal colours across gases therefore need not represent equal values. The plotted pressure is outlet-referenced, not absolute pressure. Cells are interpolated before slicing, whereas the volume-maximum scan retains the original cell values. Processing one case at a time limits memory demand without changing these conventions.

The archived sound-speed JSON files identify CoolProp 8.0.0 and its HEOS hydrogen and nitrogen models as the evaluation source~\cite{coolprop2014,leachman2009,span2000}. Their densities are approximately $33.7903$ and $481.6319\,\mathrm{kg\,m^{-3}}$; the prescribed CFD densities in Table~\ref{tab:app_properties}, rather than these independently evaluated densities, are used for pressure, force and mass-flow conversion.

\section[Reproducing the Response Fit]{Independent Reproduction of the Response Fit}
\label{sec:app_plotly_script}

The executable implementation is provided in \path{design_tool/model.py}, with plotting separated into \path{design_tool/charts.py}. A compact independent check is more useful here than a duplicate listing of the complete interface. For either force or pressure loss, let $R_i$ be the three terminal means. Minimizing $\sum_i(R_i-k_RU_i^2)^2$ gives
\[
k_R=\frac{\sum_i U_i^2R_i}{\sum_i U_i^4},\qquad
\widehat R(\dot m)=k_R\left(\frac{\dot m}{\rho A_{\mathrm{in,mesh}}}\right)^2.
\]
The same procedure is applied independently to each gas and obturator. It fits the available means with equal weights and does not force the parabola through all three points. The archived maximum relative force-fit mismatch is about $15.65\%$ for hydrogen B; for the other seven pairs it is below $2.82\%$.

\subsection{Worked Reproduction Example}
\begin{lstlisting}[language=Python,numbers=none,caption={Independent hydrogen A check, run from the repository root.}]
import csv
from pathlib import Path

source = Path("design_tool/data")
with (source / "final_high_pressure_responses.csv").open() as f:
    rows = [r for r in csv.DictReader(f)
            if r["gas"] == "H2" and r["obturator"] == "A"]
u = [float(r["velocity_m_s"]) for r in rows]
force = [float(r["mean_axial_force_N"]) for r in rows]
drop = [float(r["mean_pressure_drop_kPa"]) for r in rows]
def fit(values):
    return sum(v*v*y for v, y in zip(u, values)) / sum(v**4 for v in u)

rho, area = 33.77, 4.658925e-5
mass = 15.0 / 1000.0  # g/s to kg/s
speed = mass / (rho * area)
print("Force [N]:", fit(force) * speed**2)
print("Pressure loss [kPa]:", fit(drop) * speed**2)
\end{lstlisting}

At $15\,\mathrm{g\,s^{-1}}$ hydrogen, this gives $U_{\mathrm{in}}\simeq9.534\,\mathrm{m\,s^{-1}}$, $\widehat F_x\simeq20.249\,\mathrm{N}$ and $\widehat{\Delta p}\simeq120.28\,\mathrm{kPa}$ for A. Its projected Mach number is approximately $0.0685$, below $0.3$, and the selected mass flow lies within the sampled interval. The calculation reproduces a fitted CFD load; interpreting it as a spring requirement still requires the mechanical closing direction and the remaining force balance.

For a reproducibility check, retain the original CSV precision, use the meshed inlet area and convert the input to kg/s before evaluation. A fit using rounded chapter tables, a nominal inlet area or an unconverted g/s input will produce a different result. The application tests additionally exercise boundary handling, invalid inputs, file integrity and exported status information.


\paragraph{Numerical acceptance checks.}
A reproduction should recover $20.249\,\mathrm{N}$ and $120.28\,\mathrm{kPa}$ for hydrogen A at $15\,\mathrm{g\,s^{-1}}$, within the rounding shown above. Classification checks should use the full-precision input data and boundary calculation:
\begin{enumerate}
\item At zero flow, the formal force and pressure loss are zero, but the status remains extrapolation because zero was not simulated.
\item At the calculated $\dot m_{0.3}$ for any gas and geometry, the estimated Mach number is $0.3$ and both design outputs are withheld. The displayed two-decimal boundary in Table~\ref{tab:app_mach_envelopes} is not precise enough for an equality test.
\item For nitrogen A at its upper sampled flow, $336.38743\,\mathrm{g\,s^{-1}}$, the projected Mach screen takes priority over coverage: the design outputs are withheld even though this flow corresponds to a simulated inlet velocity.
\end{enumerate}
These checks verify units and decision logic; they are not additional validation of the CFD model.

\section{Illustrative Case Preparation}
\label{sec:app_doe_gen}

The following generator documents the 24-case factor combinations and preserves the template. It is an illustrative reconstruction, not the original submitted script. The clean template must contain the tokens \texttt{FLUX\_VALUE}, \texttt{NU\_VALUE} and \texttt{RHO\_VALUE} in the indicated files. The density token must replace the active force-function \texttt{rhoInf} value, not a commented entry. The geometry names below follow the documented A--D mapping and must match the supplied STL files.

\begin{lstlisting}[language=Python,numbers=none,basicstyle=\ttfamily\footnotesize,caption={Illustrative case generation with explicit template checks.}]
from itertools import product
from pathlib import Path
import shutil

fluids = {"H2": ("33.77", "2.709e-07"),
          "N2": ("481.352", "7.932e-08")}
shapes = {"A": "3Fori_1p5mm.stl", "B": "3Fori_3mm.stl",
          "C": "6Fori_1p5mm.stl", "D": "6Fori_3mm.stl"}
base, stls = Path("CASE_BASE"), Path("Geometrie_STL")
target = Path("DoE_Cases")
for gas, speed, obt in product(fluids, (5, 10, 15), shapes):
    rho, nu = fluids[gas]
    edits = {
        "0/include/initialConditions": ("FLUX_VALUE", str(speed)),
        "constant/physicalProperties": ("NU_VALUE", nu),
        "system/forces": ("RHO_VALUE", rho),
    }
    # Validate inputs before creating this case.
    texts = {}
    for name, (token, value) in edits.items():
        text = (base / name).read_text()
        if text.count(token) != 1:
            raise ValueError(f"Expected one {token}: {name}")
        texts[name] = text.replace(token, value)
    shape = stls / shapes[obt]
    if not shape.is_file():
        raise FileNotFoundError(shape)
    case = target / gas / f"Sim_{gas}_Flux{speed:02d}_Obt_{obt}"
    if case.exists():
        raise FileExistsError(case)
    shutil.copytree(base, case)
    for name, text in texts.items():
        (case / name).write_text(text)
    shutil.copyfile(shape, case / "constant/geometry/wallObt.stl")
\end{lstlisting}

Case creation alone does not establish a valid mesh or solution. Before submission, inspect patch names, the active force density and the geometry assignment; retain the meshing log and mesh-quality checks for each generated case. The executable design tool uses audited results from the completed campaign and does not invoke this illustrative generator.

\section{Execution and Result Retrieval}
\label{sec:app_slurm_scripts}

The sequence below summarizes the meshing and solving stages for a fresh OpenFOAM~10 case. It is an execution outline, not a portable SLURM submission file: the account, partition, modules, memory and wall-time requests depend on the cluster configuration. Here \texttt{NPROCS} must match \texttt{numberOfSubdomains} in the case's decomposition configuration. Run it only inside a generated case, retaining each log separately.

\begin{lstlisting}[language=bash,numbers=none,caption={Illustrative parallel execution sequence after environment setup.}]
set -euo pipefail
: "${NPROCS:?Set NPROCS to the decomposition count}"
blockMesh > log.blockMesh 2>&1
surfaceFeatures > log.surfaceFeatures 2>&1
decomposePar -copyZero > log.decomposePar 2>&1
mpirun -np "$NPROCS" snappyHexMesh -overwrite -parallel \
  > log.snappyHexMesh 2>&1
mpirun -np "$NPROCS" checkMesh -parallel > log.checkMesh 2>&1
# Review mesh quality before running the following solver step.
mpirun -np "$NPROCS" simpleFoam -parallel > log.simpleFoam 2>&1
\end{lstlisting}

\subsection{Directory-Preserving Retrieval}
\label{sec:app_scp_script}

The example below reads a configured remote case root from the environment and copies integral histories into a separate local archive. It uses the same illustrative naming convention as the generator. Actual remote directories must be verified before running it. Retrieval is sequential and an existing local case directory causes the example to stop, avoiding an accidental mixture of two transfers.

\begin{lstlisting}[language=Python,numbers=none,caption={Illustrative retrieval of integral histories.}]
from itertools import product
from pathlib import Path
import os
import subprocess

# Example format: user@host:/absolute/path/DoE_Cases
remote = os.environ["EFV_REMOTE_ROOT"].rstrip("/")
archive = Path("Retrieved_Results")
for gas, speed, obt in product(("H2", "N2"), (5, 10, 15), "ABCD"):
    name = f"Sim_{gas}_Flux{speed:02d}_Obt_{obt}"
    case = archive / gas / name
    case.mkdir(parents=True, exist_ok=False)
    source = f"{remote}/{gas}/{name}/postProcessing"
    subprocess.run(["scp", "-r", source, str(case)], check=True)
\end{lstlisting}

Integral histories alone are insufficient for contours or a volume-wide velocity maximum. Those operations also require the complete mesh and the selected velocity and pressure fields for every processor subdomain. Complete and verify the transfer before post-processing; missing subdomains can invalidate a maximum or prevent the mesh from loading. Preserve source simulations and write all derived outputs to a separate directory.

\section{Running and Auditing the Design Tool}
\label{sec:app_tool_operation}

The \path{design_tool/} directory contains the application, model, plots, tests and input bundle. Python~3.13 is the tested runtime. On Windows, run \path{design_tool/run_windows.cmd}; dependencies are installed at \verb|%USERPROFILE%\.efv-tool\py313| to avoid long package paths. The application opens in a browser and requires Python plus its dependencies; it is not a standalone compiled executable.

On macOS or Linux, run the following from \path{design_tool/}. Installation requires access to the packages; calculations subsequently use bundled data without OpenFOAM or ParaView.
\begin{lstlisting}[language=bash,numbers=none]
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run streamlit_app.py
\end{lstlisting}

\paragraph{Interpreting the output.}
Select the gas and threshold in g/s, then compare all four geometries. The plots and exported CSV distinguish:
\begin{description}
\item[Within the sampled range:] a regression estimate supported by the computed points, subject to their numerical limitations.
\item[Extrapolation:] additional CFD is needed before spring selection, even if the estimated Mach number is below $0.3$.
\item[Mach limit reached:] design force and pressure fields are blank. A separately labelled formal force projection is not a design load. This rule takes priority over the sampled-range classification.
\end{description}

The CSV retains the state, area, fit mismatch, variability, revision and force convention. Zero flow returns the imposed zero-load limit but is classified as extrapolation; negative or non-finite input is rejected. No output defines spring stiffness or certifies closure.

\paragraph{Verification and future updates.}
Install the development dependencies listed in \path{requirements-dev.txt}. From the application directory, run \texttt{python -m pytest tests -q}. The script \path{make_thesis_figures.py} regenerates the figures and model summary. Startup checks verify input hashes. For a new campaign, review units, state, geometry, averaging and field completeness before updating the bundle; new hashes alone do not validate predictions.

\subsection{Data Provenance and Evaluation Records}
\label{sec:app_data_record}

The manifest \path{data/provenance.json} records the full source revision (abbreviated \texttt{d3778e3}) and SHA-256 hashes. Original integral means are in \path{analysis/final_high_pressure_responses.csv}; velocity and sound-speed records are under \path{Results/Chapter4/}. Their copies in \path{design_tool/data/} make the application independent of the simulation directories.

For exact reproduction, retain the archived sound speeds rather than silently recomputing them with a different library version or fluid backend. The prescribed CFD density and viscosity describe the simulated campaign; the equation-of-state density is a separate diagnostic. Replacing one with the other would change the mass-flow axis and dimensional response conversions. A change of reference state therefore requires a new, consistently documented data set rather than only replacing the property values in the interface.

When archiving a design evaluation, retain the selected gas and mass flow, obturator identifier, assessment status and exported CSV together with the application revision and the data manifest. The manifest's source revision identifies the underlying CFD data, not necessarily the revision of the application that produced the export. Recording both revisions distinguishes a data update from a change to fitting, screening or presentation.
