\chapter{Development of the Interactive Selection Tool}
\label{ch:selection_tool}

The CFD investigation produces relationships between gas properties, inlet velocity, obturator geometry, pressure loss and axial force. An interactive application makes these relationships accessible to the engineer without requiring the user to operate OpenFOAM or inspect individual solver files. Python and \texttt{Streamlit} provide the proposed graphical interface, while \texttt{Plotly} provides interactive visualizations \cite{streamlit_docs,plotly_docs}. The intended role is to support comparison and screening of EFV concepts for hydrogen refuelling systems, not to substitute for the qualification and testing of a hydrogen-service valve \cite{iso19880_3}.

\section{Software Architecture and Data Aggregation}
\label{sec:software_architecture}

The workflow distinguishes offline numerical data reduction from online engineering interaction. CFD cases are first generated, solved and post-processed. Their integral quantities can then be collected in a compact response table, which the interface reads without loading the volumetric mesh or individual field files.

\begin{enumerate}
\item \textbf{Case identification:} Each record is associated with gas, reference fluid properties, inlet velocity, obturator identifier, number of holes and individual hole diameter.
\item \textbf{Raw response extraction:} The pipeline reads inlet and outlet kinematic-pressure averages, the integrated velocity at the inlet, and the pressure and viscous components of obturator force.
\item \textbf{Consistent data reduction:} A documented terminal averaging interval is applied to each case so that the same estimator is used throughout the comparison.
\item \textbf{Dimensional interpretation:} The kinematic pressure difference is multiplied by the reference density to obtain pascals. Force outputs generated by OpenFOAM's \texttt{forces} function object already include its reference density and must not be multiplied again.
\item \textbf{Derived indicators:} If required, the pressure-loss coefficient and axial-force coefficient are calculated using the same inlet reference area, density and velocity convention.
\item \textbf{Presentation:} Tables and comparative plots are prepared for use in the engineering interface.
\end{enumerate}

This architecture preserves traceability between the underlying CFD model and the displayed result. It also reduces the risk of inconsistent units or ambiguous force signs when passing the dataset to another user or engineering team.

\section{User Inputs and Valve Comparison Procedure}
\label{sec:recommendation_logic}

The proposed interface allows the engineer to select a working fluid, flow condition and candidate obturator geometry. Where available from the component specification, the engineer may also specify a maximum allowable pressure drop in normal service and a mechanical actuation criterion associated with the spring and seat design. The CFD comparisons are then organized to address the two competing design objectives discussed in Section~\ref{sec:efv_design_parameters}: limiting flow resistance and providing hydrodynamic loading.

A practical sequence is to select the operating point, display pressure-loss and axial-force curves for the four geometries, compare nominal losses with the allowable value, and project the fluid-force vector onto the mechanical direction of motion. A closing-force comparison requires forces to be expressed with compatible sign conventions and at a specified obturator position. The simplified inequality $F_{\mathrm{fluid,close}}\geq F_{\mathrm{spring}}$ can serve as an initial screening relationship but does not replace a displacement-dependent force balance or determine the transient closure time.

The presentation should make the trade-off explicit instead of automatically labeling the geometry with the greatest force as optimal. A candidate that produces substantial fluid force could also impose a high pressure penalty during normal refuelling. The final comparison therefore depends on which operating constraints the company assigns to the component.

\section{Interpolation and Application Limits}
\label{sec:selection_coverage}

For each discrete geometry, response curves can be displayed at the simulated inlet-velocity levels. Interpolation within that interval may be used for comparative visualization if its method and assumptions are stated. Interpolation between different numbers of holes or hole diameters is not equivalent to a validated continuous design model; it requires an explicit surrogate model or additional CFD points.

The intended hydrogen-refuelling use case brings pressures, temperatures and filling transients beyond the information contained in a single reference-state, incompressible CFD calculation. SAE~J2601 describes dispensing protocols and operating constraints, while ISO~19880-1 and ISO~19880-3 address station and valve safety \cite{sae_j2601,iso19880_1,iso19880_3}. Consequently, any input describing a new thermodynamic state must be associated with appropriately evaluated fluid density, viscosity and an assessment of compressibility. A change in pressure or temperature should not be represented solely by multiplying an existing force result by a density ratio, since Reynolds number and local flow structure may also change.

\section{Reference-State Selection for Dispenser-Line Use}
\label{sec:tool_430bar}

The industrial application places the EFV downstream of the hydrogen pre-cooler, near the dispenser (Figure~\ref{fig:station_efv_location}). The primary application-oriented condition is approximately $430\,\mathrm{bar}$ absolute and $-40\,^{\circ}\mathrm{C}$, while the ambient-property runs provide a separate numerical reference. The software should therefore associate every CFD response with its gas, selected thermodynamic state, kinematic viscosity, force-reference density and inlet-velocity setting.

For a user-specified operating state, the application must not simply convert an ambient result into a high-pressure prediction using a density multiplier. The Reynolds number, mass-flow equivalence and possible compressibility effects must be considered. If results obtained at different states are compared at equal velocity, the resulting mass-flow difference should be reported; if the engineering requirement instead specifies equal mass flow, the inlet velocity must be adjusted consistently \cite{white2016,nist_refprop_online}. The SAE~J2601 T40 context and ISO~19880-3 valve-safety scope define the intended application, but a fluid-dynamic comparison remains distinct from a certified EFV actuation or station-safety assessment \cite{sae_j2601,iso19880_3}.

\section{Traceability and Presentation for Industrial Use}
\label{sec:industrial_traceability}

An industrial comparison requires that each reported quantity can be reproduced from a defined set of inputs. For this reason, the response dataset should retain the geometry revision, OpenFOAM version, model settings, boundary-condition values, reference fluid properties, averaging procedure and the sign of the reported force. Plot axes and tabular headings must include dimensions and units.

By retaining this provenance, the application connects an otherwise complex CFD study to a transparent set of engineering design choices. The tool complements analytical force-balance models and subsequent prototype testing, but it is not a certification of mechanical actuation or compliance with hydrogen valve standards \cite{iso19880_3,moukalled2016}.
